Calculus 1, outcome by outcome

The MATH 140 map lays out every learning outcome in McGill's Calculus 1. Each one opens into a guided Learn walkthrough and endless verified practice, with tags showing what it builds on.

Analytical dynamics, from the ground up

The MECH 419 atlas maps every idea in McGill's analytical dynamics course, from generalized coordinates and Lagrange's equations to Hamilton's principle and vibrations, together with the earlier-course foundations each one quietly assumes. Every idea has a live model, an analogy with where it breaks, and step-by-step practice with checked answers.

Engineering optimization, in theory and in code

The MECH 559 atlas maps McGill's engineering systems optimization course, from problem formulation and surrogate models to line searches, Newton and quasi-Newton methods, KKT conditions and SQP. Each idea has a live model and pencil-free practice, and every course exercise is broken into guided steps. Its Code lab explains the SciPy, NumPy and scikit-learn functions the assignments use and catalogues 33 common bugs, each run for real, with what you'd see and how to fix it.

Compressible flow, one nozzle at a time

The MECH 430 atlas maps McGill's compressible fluid dynamics course, from the speed of sound and isentropic nozzle flow to normal and oblique shocks, friction and heat addition, Prandtl–Meyer expansions and the method of characteristics. Sixteen simulators let you push the flow around (lower a nozzle's back pressure and watch it choke, shock and leave the nozzle), every worked example in the course notes is rebuilt step by step, and a Code track has you write your own gas tables in Python that runs right in the page.

How the ideas connect

After you answer a step in any problem, a "Why is this the case?" button opens a network of explanations that goes all the way down to first principles. The concept atlas shows the whole network on one page.

Endless practice

Want more? The practice page serves a fresh, verified problem every time: integration by parts, aiming a projectile, mixing drinks and bouncing balls, each in several levels.

How these are designed

Every problem starts with something to try, not something to read. Each step targets one common misconception, and every wrong answer gets feedback written for that specific mistake. The math is generated by code and checked by automated tests, so what you see on screen is exactly what the math says.
