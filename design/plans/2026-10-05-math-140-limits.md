- Nine new "Why?" concepts.

**Tech Stack:** Static site under `docs/`, Python + SymPy generators and checkers, JavaScriptCore widget tests, Playwright browser tests.

**Spec:** `design/specs/2026-10-05-math-140-explorer-design.md`. §1 names 140.2 as the next unit, built on the same pattern; §§3–7 define that pattern. ## Global Constraints
- Base content on McGill's official description; CLP books are inspiration only (no copied text or problems).
- Every banked problem passes the validator pipeline, and the audit rebuilds it from its seed. Target: 100 problems per level.
- Data files are `window.X = <JSON>`. No escaped `\$` in walkthrough text, and `**bold**` is allowed.
- Each walkthrough asks before it explains. Every choice step has exactly one correct option, and every wrong option has feedback. Every claim is SymPy-proven.
- Phone (390 px) and desktop: no sideways scroll and no JS errors.
- No private material (`notes/`, `knowledge/`, PDFs) in the public repo.

## Review Focus
1. **A limit that exists while f(a) doesn't, or differs from f(a)** (removable discontinuity): the practice and walkthrough must never treat the limit as f(a). Tested in Task 2 (one-sided families) and Task 4 (continuity).
2. **The IVT converse** (same signs at the ends doesn't mean no root): the correct answer is "no guarantee", never "no root". Tested in Task 4.
3. **A hole versus a vertical asymptote**, when a factor cancels: the hole must never be called an asymptote. Tested in Task 3.
4. **Squeeze bounds that don't meet** (−1 ≤ f ≤ 1): offered only as a wrong option, with feedback. Tested in Task 3.
5. **Tables whose last row is still visibly off the limit:** the tolerance must accept the true limit, and the closest table value must not be offered as a separate distractor within 10%. Tested in Task 2.
